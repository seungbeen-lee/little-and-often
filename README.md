## 프로젝트의 원칙

### 하나의 자료, 일관된 등록·학습 방식

카드를 등록하는 방식과 시험 흐름을 최대한 유지합니다. 같은 카드로 키워드 채우기, 전체 쓰기, 연결 학습, 카드 보기와 퀴즈를 이용합니다. 표를 외운다고 모든 칸을 별도 카드로 쪼개 문제 수를 과도하게 늘리지 않습니다.

**답의 굵은 글씨는 출제할 키워드**입니다. 질문의 굵은 핵심어는 연결 학습 등의 단서로 사용합니다. 표에서도 보여줄 설명은 그대로 두고 회상할 부분만 굵게 지정합니다.

### 연습과 실전, 독립 회상과 교정을 구별

연습은 입력과 회상을 익히는 과정이며 카드·키워드 정오답 성적이나 숙달 단계를 올리지 않습니다. 실전은 첫 풀이·재도전·힌트 사용을 구분합니다. 정답 확인이나 교정 입력 완료만으로 독립 회상에 성공했다고 간주하지 않습니다.

모드는 시작할 때 선택하고 세션 중 임의로 전환하지 않습니다. 이어하기에는 진행 위치와 모드를 함께 보존합니다. 표의 일부만 푼 결과로 표 전체의 숙달을 인정하지 않습니다.

### 카드보다 작은 단위도 기록하되 맥락을 보존

키워드별 취약도를 기록하고 약한 부분을 따로 복습합니다. 전체 자료는 한 카드에 두어 맥락을 잃지 않도록 합니다. 표 키워드는 독립 식별자를 가져 같은 표현이 다른 칸에 있어도 기록이 섞이지 않게 합니다.

숙달한 카드는 보관하고 간격을 두어 다시 확인합니다. 편집이나 재시도가 기존 기록을 소급해서 바꾸거나 중복 반영하지 않도록 합니다.

### 정확한 표현과 나열의 유연성

띄어쓰기·따옴표 등의 표기 차이는 정규화하되 핵심 단어가 다른 답을 무조건 인정하지 않습니다. 순서가 의미 없는 나열은 같은 문맥 안에서 순서를 바꾸어도 인정합니다. 표에서는 서로 다른 칸의 답을 교환해 정답으로 처리하지 않습니다.

### 학습을 방해하지 않는 화면과 입력

힌트와 입력은 같은 자리·같은 크기로 보여줍니다. 힌트 사용 시 화면이 위로 튀거나, 모바일 키보드가 커서를 가리거나, 입력 영역이 하단 버튼과 겹치는 일을 줄입니다. PC 키보드와 모바일 터치에서 같은 규칙으로 편집할 수 있어야 합니다.

과목 색, 분류 띠, 작은 오답 표시와 간결한 정보 줄을 사용해 본문 배치를 덜 방해합니다. 학습 완료는 색뿐 아니라 문구로도 전달합니다. 과목 색은 다음 그룹 안에서 닮되 구별되게 구성합니다.

- 총론 · 창체 · 통합
- 국어 · 영어 · 수학 · 과학
- 사회 · 도덕 · 미술 · 음악
- 실과 · 체육

### 업데이트가 학습 자산을 지켜야 한다

최신 변경과 사용자 데이터를 확인한 뒤 필요한 부분을 수정합니다. 카드·표 식별자와 기존 기록을 보존하고, 표기 정리와 학습 내용 변경을 구분합니다. 정답 확인 뒤 편집해도 이미 채점한 결과는 당시 내용으로 유지합니다. 구조 변경은 마이그레이션과 관련 검증으로 남깁니다.

## 현재 반영된 기능

### 카드·과목·세트 관리

- 과목, 분류, 섹션·하위 섹션, 중요 표시, 질문·답·메모를 포함한 카드 관리.
- 현재 저장 분류: 교육과정, 교과교육론, 각론, 수업모형, 지도서총론. 이전 `교육론`·`기타` 이름도 호환.
- 검색, 과목·중요 표시·보관 여부 등의 필터와 정렬.
- 여러 카드 편집, 섹션 접기·이동과 하위 항목을 포함한 묶음 이동.
- Shift+클릭 범위 선택, Ctrl/Cmd+클릭 개별 선택, 선택 카드로 세트 만들기.
- 세트 이름·설명·카드 순서 관리와 세트 단위 학습·퀴즈 구성.
- 질문·답·메모 사진 첨부, 크기·배치·자르기와 필드 사이 사진 이동.
- 한글 입력을 고려한 실행 취소·재실행, 목록·서식 복사·붙여넣기.
- 사용자별 목표 날짜와 한국 시간 기준 D-day.

### 범위 선택·이어하기·오늘 학습

- 시작·끝 번호 대신 섹션·카드를 눌러 범위에 추가·제외. 전체 선택·전체 해제와 분류별 범위 선택.
- 오답 카드의 학습 범위를 과목별로 좁히고, 과목을 바꿔도 이미 선택한 카드를 유지.
- 오답 카드의 **오늘 복습**에서 한국 시간 기준 오늘 실전이나 퀴즈에서 틀린 카드를 다시 풀이. 오답 카드는 세션 끝에 다시 출제하고 정답을 맞히면 남은 복습 대상에서 제외.
- 시작 창에서 실전·연습 선택 후 바로 시작. 세션 도중 모드 고정.
- 이어하기는 다음 카드와 모드를 기억하고, 남은 순서의 마지막 카드에서 종료. 처음으로 순환하지 않음.
- 오늘 학습량·정답률·과목별 상태 표시.
- 한국 시간의 하루 안에 해당 과목의 활성 카드 전체를 학습하면 완료 표시. 보관 카드나 빈 과목을 근거로 잘못 완료 처리하지 않음.

### 단계별 학습과 보관

기본 흐름은 **키워드 쓰기 → 전체 쓰기 → 보관 복습**입니다. 정답을 보며 따라 쓰는 연습은 필요할 때 선택합니다.

| 단계 | 진행 기준 |
| --- | --- |
| 키워드 쓰기 | 전체 범위를 힌트 없이 연속 3회 성공하면 전체 쓰기로 이동 |
| 전체 쓰기 | 키워드 단계를 충족한 상태에서 힌트 없이 연속 2회 성공하면 자동 보관 |
| 연습·교정·부분 풀이 | 독립적인 전체 회상 성공으로 승격하지 않음 |
| 보관 복습 | 1·3·7·14일 간격을 사용하고 마지막 간격은 14일로 유지 |

키워드 단계의 오답·힌트 사용은 연속 성공을 끊습니다. 전체 쓰기에서 오답·힌트를 사용하면 전체 쓰기 연속 성공을 초기화합니다. 보관 복습에서 틀리면 보관에서 꺼내 다시 학습합니다. 수동 보관·해제와 보관 카드만 대상으로 하는 퀴즈도 지원합니다.

시험 직전 설정으로 **2026-11-07 00:00 KST 전에는 마지막 키워드 성공의 유효기간이 3일, 이후에는 7일**입니다. 보관되지 않은 카드의 유효기간이 지나면 단계 진행을 다시 시작하되 누적 성적은 지우지 않습니다. 다음 시험에 맞춘 수정은 `lib/learning-stages.ts`의 날짜 정책을 확인해야 합니다.

복습 간격은 앱의 운영 설정이며 개인별 기억력을 추정하는 모델이나 모든 사람에게 검증된 최적 간격을 뜻하지 않습니다.

### 퀴즈·힌트·오답 교정

- 정오답·응답 시간·복습 시점·키워드 취약도·연결 기록 등을 반영한 기본 5문제 추천.
- 최근 30분의 기록을 이용한 출제 후보 제외, 세트 카드의 연속 구성과 중복 제거.
- 취약 키워드 추가 복습. 현재 후보 기준: 시도 3회 이상, 오답 2회 이상, 오답률 60% 이상.
- 첫 음절 → 초성 힌트. 맞힌 접두 부분은 유지하고 잘못 쓴 나머지는 정리. 나열형은 정답 판정과 같은 그룹 규칙으로 힌트 배정.
- 회색 힌트와 실제 입력을 같은 자리에 표시. 정답 칸은 초록색으로 전환·크기 조절·다음 칸 이동. 지원 브라우저에서는 짧은 진동.
- 틀린 키워드는 원래 자리에서 다시 써야 다음 문제로 이동 가능. 교정 칸은 붉은 표시 유지.
- 학습의 정답과 따라쓰기 글씨는 PC에서 18px를 기본으로 하고, 긴 답은 영역에 맞춰 크기를 조절. 모바일 따라쓰기 입력은 17px 사용.
- 정답 화면의 편집은 현재 채점 결과를 유지하고 이후 풀이에 반영.
- PC Enter는 활성화된 다음 문제 버튼과 동일하게 동작.
- 새 5문제는 두 번 눌러 확인하는 방식으로 실수 방지.

실전 학습과 퀴즈의 카드 결과 처리는 다음과 같습니다.

| 풀이 | 카드 결과 기록 | 재도전 |
| --- | --- | --- |
| 첫 풀이, 힌트 없이 정답 | 정답 1회 | 없음 |
| 첫 풀이, 힌트 사용 후 정답 | 이 시점에는 정답·오답 추가 없음 | 진행 |
| 첫 풀이 오답, 힌트 여부 무관 | 오답 1회 | 진행 |
| 재도전 정답 | 정답 1회 | 완료 |
| 재도전 오답 | 추가 오답 없음 | 교정 흐름 유지 |
| 연습 | 카드·키워드 정오답 성적을 올리지 않음 | 연습 흐름 사용 |

재도전에서는 힌트를 사용할 수 없습니다. 연습도 오늘 학습 여부 등의 활동 기록에는 남을 수 있지만 실전 성적·숙달과 구분합니다.

카드의 표시용 오답 횟수는 누적 오답 총계와 다릅니다. 현재 복습 규칙에서는 정답으로 남은 오답 부담을 줄이며, 오답 1회가 남았을 때는 정답 두 번으로 해소합니다. 누적 정답 수와 실전 통계는 별도 기록을 사용합니다. 관련 코드는 `lib/archive-schedule.ts`, `app/api/reviews/route.ts`, `app/study-app.tsx`입니다.

### 타이머·일시정지

- 학습 실전과 퀴즈가 같은 계산 사용: **고민 시간 20초 + 남은 키워드 글자 수만큼의 초 + 긴 질문의 읽기 시간**. 모바일은 20초 추가.
- 질문은 공백·서식을 제외한 50자를 넘으면 초과 5자당 1초를 올림.
- 정답 확인 단계에서는 타이머 정지.
- 시간 표시 칸에서 일시정지·재개. 정지 중 입력·채점 차단.
- 원래 작은 시계를 유지하면서 중앙으로 확대·축소되는 전환.
- Esc로 일시정지·재개, 일시정지 상태에서 Enter로 재개.

### 표 한 장을 하나의 카드로

- 질문은 표 제목, 답은 표 전체. 별도 표 카드 DB 대신 기존 `answer_format`에 `[table:v1]` 문서 저장.
- 행·열, 병합 셀, 회색 음영, 열 너비·정렬, 셀·키워드 식별자 보존.
- 굵게 지정한 부분만 빈칸으로 출제. 전체·일부 범위 학습과 키워드별 기록.
- 행·열 추가·삭제, 병합·해제, 다중 선택, 키워드 지정, 실행 취소·재실행.
- 열 경계 드래그·Shift+방향키 너비 조절, 열 너비 고정·해제·전체 균등 배분.
- **F8 또는 하단 정렬 아이콘**으로 왼쪽 → 가운데 → 오른쪽 → 양쪽 순환. 여러 칸은 맨 위·왼쪽 칸을 기준으로 함께 변경.
- PC·모바일 하단 편집 도구. 모바일은 두 줄 배치, 키보드에 맞춘 편집 영역과 커서 노출.
- 편집 중 자동 적용, 닫을 때 마지막 변경 반영, 적용 실패 시 확인·재시도.
- 표 크게 보기, 모바일 가로 보기·터치 스크롤, 편집 시 열 비율 유지.
- 사진을 잘라 표로 변환하고 사용자가 확인한 뒤 적용. 인식 결과는 임의로 굵은 키워드를 지정하지 않음.
- 선택 영역을 템플릿으로 저장하고 빈 행 두 개 추가. 불러오면 새 식별자를 생성해 원본 학습 기록을 복제하지 않음.
- 현재 한도: 표 400칸, 키워드 2,000개. 번호·목록·괄호·줄바꿈의 표시와 출제 경계를 구분.

### 보기·입력 편의

- 카드 정보 줄의 과목·분류·중요 표시와 섹션 경로, 과목별 색상과 분류 띠.
- 표로 전체 보기: 질문 영역 전체 클릭으로 편집, 답 클릭으로 숨김·표시.
- 연결 학습: 질문의 핵심어와 정답 내용을 연계해 회상.
- F1 화면별 도움말과 한글 조합 중 이동 단축키 오작동 방지.
- 표 학습 Tab 이동 방향을 세로·가로로 선택해 빈칸 번호에 반영. 방향키는 실제 칸 위치·줄바꿈을 고려.

## 개발 환경

Node.js **22.13 이상**이 필요합니다. 설치·빌드 래퍼는 Bash와 Linux 도구(`flock`, GNU `timeout`, `curl`, `sha256sum`)를 사용하므로 **Linux 또는 WSL**을 권장합니다.

```bash
git clone https://github.com/seungbeen-lee/little-and-often.git
cd little-and-often
npm run install:ci
npm run dev
```

Windows PowerShell에서는 Bash 의존 스크립트와 `WRANGLER_LOG_PATH=...` 형태의 환경 변수 지정이 그대로 실행되지 않습니다. 해당 환경을 준비하거나 개발 서버는 `npx vite`, 빌드는 `npx vinext build`로 직접 실행할 수 있습니다. 직접 실행은 저장된 제한 시간 등의 래퍼를 거치지 않습니다.

```bash
npm run typecheck   # TypeScript 검사
npm run build       # Workers용 빌드
npm test            # 타입 검사 → 빌드 → Node 테스트
npm run db:generate # 스키마 변경 후 마이그레이션 생성
```

브라우저 검증 스크립트에는 Playwright와 사용 가능한 브라우저가 필요합니다. 지원 스크립트는 `KEYWORD_BROWSER_MODULE`로 모듈 경로를 지정할 수 있습니다. 검증 fixture는 실제 사용자 데이터와 분리됩니다.

### 실행 환경과 데이터

- `.openai/hosting.json`은 기존 Site ID와 `DB`(D1), `UPLOADS`(R2) 논리 바인딩을 유지합니다. GitHub에 소스를 올리는 것만으로 서비스 배포나 데이터 복사가 이루어지지는 않습니다.
- 로그인·소유권 확인은 Sites가 전달하는 인증 헤더에 의존합니다. 일반 호스팅으로 옮긴다면 같은 신뢰 경계의 인증 계층을 구성해야 합니다. 외부 요청이 인증 헤더를 임의 지정하게 두면 안 됩니다.
- 로컬에는 플랫폼 로그인 정보가 없어 사용자 API가 401을 반환할 수 있습니다. 실행만으로 운영 계정·학습 자료를 읽을 수 있는 구조가 아닙니다.
- 사진 표 변환에는 서버 런타임의 `OPENAI_API_KEY`가 필요합니다. 키가 없어도 수동 표 편집은 가능합니다. 변환할 사진은 API로 전송되며 사용료가 발생할 수 있습니다.
- API 키·인증 토큰·환경 파일·개인 DB·사진 원본은 Git에 넣지 않습니다. 의존성·빌드 결과·로컬 런타임 상태도 제외합니다.
- D1 마이그레이션과 R2 파일 이전은 소스 업로드와 별도입니다. 실행 환경 변경이나 DB 초기화 전에는 기존 데이터를 보존해야 합니다.

## 이후 수정 시 확인할 것

1. 최신 배포 소스와 작업 중인 변경을 확인한 뒤 필요한 부분을 수정합니다.
2. 새 편집 기능은 PC 단축키와 모바일 터치 접근을 함께 고려합니다.
3. 연습·실전, 첫 풀이·재도전, 힌트·교정·부분 풀이의 기록 정책을 검증합니다.
4. 정답 확인 뒤 편집이 이미 채점한 결과를 바꾸지 않는지 확인합니다.
5. 표 구조 변경 후에도 셀·키워드 ID와 통계가 의도대로 유지되는지 확인합니다.
6. 모바일 키보드, 한글 조합, 스크롤, 긴 입력과 표를 실제 화면 흐름에서 확인합니다.
7. 스키마 변경은 마이그레이션으로 남기고 이 문서도 실제 동작과 함께 갱신합니다.
